# AstraTube：整片雙語字幕與翻譯快取

## 一般使用者

1. 先分析一部 YouTube 或 Bilibili 公開字幕影片（或匯入自己的 SRT／VTT），播放器下方會顯示可搜尋的時間戳字幕。
2. 按「翻譯整支影片（N 句）」，AstraTube 會**從目前播放位置開始**，一次 16 句依序翻成台灣繁體中文，後面翻完再回頭補前面。翻譯中可以按「暫停」；之後按「繼續翻譯（剩 N 句）」接著做。
3. YouTube 影片的字幕會疊在播放器下方，用「無／原文／中文／雙語」切換；選擇會記在這台電腦，下次開啟沿用。尚未翻到的句子在「中文」模式會先顯示原文。
4. 下方字幕列表可勾選「字幕列表顯示中文」，點任一句可跳到該時間。
5. 翻譯失敗（例如 AI 服務限流）會停下並顯示**真正原因**，原文與已翻好的句子都保留，稍後按「繼續翻譯」即可。

**限制**
- Bilibili 站外播放器無法回報播放進度，所以**不會**把字幕疊在 Bilibili 影片上，只能在下方列表對照。
- 疊加字幕顯示在 AstraTube 畫面上，不在 YouTube 播放器內部；按 YouTube 播放器的「全螢幕」時看不到疊加字幕。
- 只翻譯平台現有或你匯入的字幕，不下載影片、不做語音轉文字。

翻譯成功的句子會存到本機 `.cache/subtitle_translations`；換頁或再次分析同段內容時會讀取快取，不再次呼叫 AI。逐句翻譯可能因模型限額、字幕缺失、平台權限或模型輸出不完整而失敗，這時原文仍保留。

## 技術限制

- 字幕翻譯與摘要、問答共用「AI 來源」選定的模型；尚未選擇時只顯示原文，不會開始翻譯。不會因為已設定其他供應商的金鑰就自動改用。
- 切換 AI 來源會重新載入對應的字幕翻譯快取，不會把其他模型譯文當成自己的。
- 如選用 Ollama，需先在「AI 來源」完成驗證連線並選擇模型。翻譯失敗只會顯示錯誤，不會回退到線上模型。
- 目前 Ollama 只支援與 AstraTube 後端在**同一環境**的 loopback 11434；Codespaces 不能直接存取 Windows 上的 GPU。
- API：`GET /subtitles?translation_provider=ollama:<model>`（或 `<供應商>:<model>`）會讀取所選引擎的本機快取；`POST /subtitles/translate` 同樣接受 `translation_provider`，每次請求處理一批（最多 16 句）；整片翻譯由前端依序送出，同一時間只有一個請求。後端只接受明確指定的已支援供應商，不接受會自動接力的 `auto`／`free`。
- 快取依「引擎＋模型＋原文＋版本」分離，保留舊版 OpenCode 已產生的快取；影片字幕的原始時間戳與字句不受翻譯模型切換影響。
- 後端從已支援的來源重新取得原文，使用者不能利用此端點直接送任意文字給 AI；模型仍會收到該批公開字幕文字，使用者須遵守內容來源及服務提供者條款。
- 模型回傳 JSON 必須完整對應原字幕的索引，否則本批失敗、不能寫入錯位的快取。
- **平台原生逐字稿**仍使用 `[整數秒]` 格式，字幕顯示區間屬估算；**使用者匯入的 SRT／VTT** 則保留原檔案的毫秒級起迄時間。這不是逐字辨識準確度的保證。
- YouTube 官方播放器可讀取進度並高亮字幕；Bilibili 站外 iframe 尚不具備相同的進度回報能力，仍以點擊字幕時間戳跳轉為主。
- 雲端模型可能下架、限流或計費，所以**目前沒有「永遠免費、每部影片都翻譯成功」的保證**。
- 已加入**本地 Ollama 字幕翻譯**的選用功能，但尚未在 Windows／WSL 實機驗收；已加入使用者持有的 SRT／VTT 匯入，但仍不包含 Windows 安裝程式或端到端真人使用驗收。
